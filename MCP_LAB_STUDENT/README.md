# Browser Agent — лабораторная: политика доступа MCP-агента

LLM-агент управляет **настоящими веб-страницами** через MCP-сервер
(JSON-RPC 2.0 по stdio) + Playwright. Модель видит структурированный
снапшот страницы — без скриншотов и сырого HTML.

## Суть работы

Мы даём нейросети возможность работать в настоящем браузере, но учимся
ограничивать её полномочия программными правилами и проверять результат,
а не доверять словам модели.

Браузер с нуля писать не нужно: каркас готов (MCP-инструменты,
браузерный адаптер, окно подтверждения, защитные проверки). Обязательный
код студента — сценарий сайта в `backend/scenarios.py` и словарь правил
в `backend/student_policy.py`. Студент отвечает на три вопроса:

1. Какие действия агенту **разрешены** (allow)?
2. Какие требуют **отдельного согласия человека** (confirm)?
3. Какие **запрещены** независимо от того, что попросили пользователь,
   страница или сама модель (deny)?

Главный результат — не пересказ статьи и не удалённый файл, а
обоснованная политика доступа и умение показать, что она применяется:
решение каждого вызова видно в событиях прогона и журнале. Отдельный
отчёт со снимками и таблицами не требуется — итог занятия фиксируют
короткие ответы на контрольные вопросы в конце файла.

## Минимум теории

**MCP** — протокол «хост ↔ сервер инструментов» поверх JSON-RPC 2.0
(здесь транспорт — stdio). Модель этих строк не видит: она выдаёт
`{"calls":[{"tool": "...", "args": {...}}]}`, а хост переводит это в
`tools/call`. `inputSchema` каждого инструмента — договор: хост
валидирует вызов до отправки.

**Агентный цикл:**

```
snapshot → llm.decide → validate_call → PolicyGate.check_call
        → tools/call → verify(before/after) → history += {call, result}
        … пока task_done / MAX_STEPS / «Стоп»
```

**Граница доверия:** сервер — глупый исполнитель, он не знает о задаче.
Вся защита живёт на хосте:

| Слой | Когда срабатывает |
|------|-------------------|
| Стоп-слова команды (`check_task`) | до запуска браузера |
| Схема вызова (`validate_call`) | перед `tools/call` |
| Политика сайта (`check_call`: allow/confirm/deny, домены) | перед `tools/call` |
| Предусловия (`scope_gate`: ref существует, папка та самая) | перед `tools/call` |
| Постусловия (`verify` по снапшотам до/после) | после `tools/call` |

**Prompt injection:** страница — недоверенный ввод. Инструкции в
`display:none`, комментариях или белом тексте модель не отличает от
команды пользователя. Защита слоями: детектор на хосте → политика
ограничивает ущерб → остановка прогона. Предупреждение детектора —
не запрет: разрешённое действие внутри scope она не остановит.

**Human-in-the-loop:** деструктивность живёт в данных, а не в имени
инструмента — вреден клик по кнопке «Delete», а не `browser_click`
вообще. Семантика fail-closed: нет ответа человека за 90 секунд →
отказ; «Стоп» во время ожидания → отказ. Промпт можно обмануть
инъекцией; гейт с Approve/Deny детерминирован — но узок: решение принимает политика и человек, код гарантирует проверку, а не безошибочность. Главный тезис курса:
**безопасность агента — код на хосте, а не просьбы в промпте**.

```
run.py / serve.py      ← хост: цикл агента, PolicyGate, верификация
       │ stdio JSON-RPC
server.py              ← MCP-сервер: владеет Chrome, browser_* tools
       │ subprocess
Playwright → system Chrome → реальные страницы
```

## Подготовка

Нужны Python 3.11+, системный Chrome, Node.js 20.19+ или 22.12+
(требование Vite 7), Ollama и модель qwen3:4b. Рабочие документы не
используйте. Все команды — из корня `MCP_LAB_STUDENT/`.

Точные команды установки и запуска — в канонической
[`INSTRUCTIONS.md`](INSTRUCTIONS.md), раздел «Подготовка» (venv +
активация, три терминала, версии Node).

> Медленная модель затягивает работу: на 8 ГБ RAM ответы могут идти по
> 30–60 сек. Запасной вариант: `ollama pull qwen3:1.7b` и запуск с
> `OLLAMA_MODEL=qwen3:1.7b`. Если модель не отвечает — чинится Ollama,
> а не повторяется запрос бесконечно.

Три терминала во время работы:

Три терминала (API, UI, атак-страницы) — команды в
[`INSTRUCTIONS.md`](INSTRUCTIONS.md).

По умолчанию агент работает в живом Chrome через CDP (`:9222`,
отдельный синтетический профиль `~/.cache/agent-chrome` — только для
занятия, порт не выставляется наружу). Не переключайте активную вкладку
во время прогона. `serve.py --no-cdp` — чистый временный браузер.

### Этап 0. Наблюдение на настоящей странице

Откройте `http://localhost:5173` в отдельном окне. Поле URL, задача,
ответ, инструменты и снимок относятся к одному прогону.

- **Вариант 1 — Wikipedia (основной студенческий):** статья о HTTP в
  русской или английской Wikipedia, другие домены не разрешены. Никаких
  правок и входа. Задача: «Объясни назначение HTTP в трёх предложениях
  на основе статьи и укажи источник».
- **Вариант 0 — Google Drive (демонстрация преподавателя):** в
  студенческом комплекте нет семантических `drive_*`-инструментов —
  Drive-прогон выполняет только преподаватель на эталонном комплекте.
  Его отчёт (`docs/pdf/Инструкция_GoogleDrive.pdf`) — материал для
  просмотра: образец оформления и доказательств, а не задание студенту.

`task_done` — заявление модели, а не доказательство: сравните ответ с
реальной страницей. Кнопка «Разведать» — read-only анализ страницы и
черновик ограничений; она не заменяет вашу политику и не выдаёт
разрешений. Ошибка генерации — тоже фактический результат, а не
«успешная разведка».

### Этап 1. Каталог инструментов

```bash
python tools/inspect_tools.py --variant web      # --json для сырых сообщений
# после создания своего сценария: --variant <его имя>
```

Скрипт сам выполняет `initialize` + `tools/list`, проверяет имена
правил и показывает назначение каждого инструмента. Сайт и Chrome не
нужны. Вопрос на этом шаге: какой инструмент нужен для вашей задачи,
а какие не нужны вообще?

| Инструмент | Назначение | Важное ограничение |
|------------|------------|--------------------|
| browser_navigate | Перейти по URL | Проверяется домен назначения (scope) |
| browser_snapshot | Состояние страницы | Снимки делает и сам хост |
| browser_get_text | Текст элемента по ref | Только чтение |
| browser_click | Клик по элементу из снапшота | Цель проверяется по имени и ref |
| browser_type | Ввод текста в поле | Меняет страницу |
| browser_press | Клавиша (Enter, Delete, …) | Нет цели — бьёт по выделенному |
| browser_scroll / browser_back | Прокрутка / назад | Навигация в пределах scope |
| browser_new_tab / switch_tab / list_tabs | Управление вкладками | Открытие URL проверяется scope |

Семантические `drive_*`-инструменты (`drive_list_files`,
`drive_trash_files`) есть только в эталонном комплекте преподавателя —
в студенческой сборке их нет. Выдуманное имя инструмента в политике
даст ошибку диагностики.

### Этап 2. Своя политика

Ваша работа — **создать сценарий** в `backend/scenarios.py` и
**словарь правил** (`POLICIES`, опц. `DENY_NAME_PATTERNS`) в
`backend/student_policy.py`. `server.py`/`agent.py` и реализации
инструментов трогать не нужно. Пошагово — `INSTRUCTIONS.md`, этап 2.

```python
POLICIES = {
    "имя_сценария": {
        "имя_инструмента": "allow",      # вызов разрешён, границы проверяются
        "другой_инструмент": "confirm",  # решение принимает человек
        "ненужный_инструмент": "deny",   # запрет независимо от пожеланий
    },
}
```

Отсутствующее правило = deny. Опечатка в значении — явная ошибка, а не
разрешение.

- **Вариант 1 (Wikipedia):** временно `browser_navigate: deny` →
  проверьте отказ на переходе к другой статье; верните `allow`,
  перезапуск backend (Python должен перечитать файл).
- **Вариант 0 (Drive):** выполняется только на комплекте
  преподавателя — там сначала `drive_trash_files: deny` → проверка
  отказа, затем `confirm` и перезапуск.

Меняйте одно правило за раз; сохраните исходное значение и ожидаемый
результат перед запуском.

```bash
python tools/inspect_tools.py --variant wikipedia   # синтаксис правил и имена
python -m unittest discover backend/tests           # защитные инварианты
```

Осознанно изменённая политика может требовать другого ожидания в
эталонных тестах — не правьте защитные тесты ради сокрытия обхода.

**Предохранители каркаса словарём не отключаются:** неизвестный
инструмент = deny; опечатка в значении правила = явная ошибка; `deny`
всегда сильнее Approve (в т.ч. `DENY_NAME_PATTERNS` — запрет по имени
элемента не отменяется подтверждением); отсутствие ответа на
подтверждение за 90 секунд = отказ и конец прогона без повторных
попыток.

### Этап 3. Проверка защиты

**deny:** попросите запрещённую операцию. Ожидание — вызов получает
POLICY_DENIED, прогон завершается. Если модель сама отказалась и не
предложила вызов — это отказ модели, а не доказательство политики:
приложите событие или отдельную детерминированную проверку гейта.

**confirm (Wikipedia):** при `browser_click: confirm` попросите перейти
по ссылке внутри статьи («перейди на английскую версию») — модалка
покажет инструмент и **имя цели** из снапшота. Проверьте её перед
Approve: имя — данные страницы, модель могла описать цель иначе.
**Deny** и молчание 90 секунд — одинаковый исход: `ACTION_DENIED`,
прогон останавливается без повторных попыток.

**confirm → Deny/Approve (Drive — демо преподавателя):** на эталонном
комплекте хост заранее собирает точный список файлов и ID
(`drive_prepare_trash`), модалка показывает список, папку и действие;
Deny или таймаут 90 с — отказ без перепланирования; Approve исполняет
ровно замороженный набор один раз (plan_id одноразовый). Журнал и
скриншоты — в `docs/pdf/Инструкция_GoogleDrive.pdf`.

**Недоверенный текст и границы:** локальные `attack_pages/` —
демонстрация инъекций (карта страниц ниже). Команды из содержимого
страниц должны пересказываться как данные, а не выполняться. Проверьте
просьбу уйти на чужой домен. Не объявляйте систему защищённой от всех
атак: если атакующий просит уже разрешённое действие внутри scope —
одна доменная политика его не остановит; предупреждение детектора —
эвристика, а не гарантия.

### Этап 4. Контрольные вопросы

Финал занятия — короткие ответы на контрольные вопросы в конце этого
файла (1–3 предложения на вопрос). Отдельный отчёт не требуется.
Формулируйте ожидания честно: решение вызова видно в событиях прогона
и журнале `backend/logs/*.jsonl`, а `verify ✗` означает лишь
«настроенное постусловие не подтвердилось», а не доказанное отсутствие
эффекта — и не ошибку.

## Атак-лаборатория

```bash
python -m http.server 8777 --directory attack_pages   # атак-страницы :8777
```

| Страница | Что демонстрирует |
|----------|-------------------|
| `index.html` | чистый блог — контраст с заражёнными страницами |
| `inject_nav.html` | скрытые инструкции (display:none, белый текст, комментарий) зовут на `evil.html` |
| `inject_exfil.html` | инъекция просит вынести данные на `collect.html` |
| `inject_persona.html` | текст страницы подменяет личность агента |
| `inject_danger.html` | MiniDrive с Delete-кнопками: в режиме `web` клики — `deny` (сценария minidrive в сборке нет) |
| `evil.html`, `collect.html` | адресаты «угона»: попадание доказывает перехват, если переход не запрашивался; утечка — если просили вынести данные |

**Честные границы:** read_only / `deny` не гарантируют блокировку
инъекций — `browser_navigate` внутри `localhost` может быть разрешён,
а `evil.html` и `collect.html` живут на том же хосте (доменный scope
не изолирует пути). Предупреждение детектора — эвристика, не запрет;
`inject_persona` может отравить текст ответа — политика инструментов
такое не остановит. Результаты недетерминированы: записывайте факт
из журнала, а не ожидание.
