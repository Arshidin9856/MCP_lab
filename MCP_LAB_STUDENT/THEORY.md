# Теория: LLM-агент + MCP + политика доступа

Материал к лабораторной «Политика доступа браузерного MCP-агента»
(пошагово — `INSTRUCTIONS.md`, быстрый старт — `README.md`).

## 1. Что такое Model Context Protocol (MCP)

MCP — протокол «хост ↔ сервер инструментов» поверх JSON-RPC 2.0.
Одна строка JSON = одно сообщение. Транспорт в этом комплекте —
**stdio**: хост запускает `server.py` как subprocess и общается с ним
через stdin/stdout.

Минимальный жизненный цикл:

```
→ {"jsonrpc":"2.0","id":1,"method":"initialize","params":{...}}
← {"jsonrpc":"2.0","id":1,"result":{"serverInfo":{...},"capabilities":{...}}}
→ {"jsonrpc":"2.0","method":"notifications/initialized"}   (без id — уведомление)
→ {"jsonrpc":"2.0","id":2,"method":"tools/list"}
← {"jsonrpc":"2.0","id":2,"result":{"tools":[{name,description,inputSchema},…]}}
→ {"jsonrpc":"2.0","id":3,"method":"tools/call",
   "params":{"name":"browser_navigate","arguments":{"url":"https://…"}}}
← {"jsonrpc":"2.0","id":3,"result":{"content":[{"type":"text","text":"…"}]}}
```

Три вещи, которые важно увидеть в лабораторной:

- **Модель никогда не видит этих строк.** Модель генерирует
  `{"calls": [{"tool": "browser_click", "args": {"ref": "e3"}}]}` — хост
  переводит это в `tools/call`. JSON-RPC — деталь транспорта, а не
  формат модели.
- **`inputSchema` — договор.** Сервер декларирует обязательные
  аргументы; хост валидирует вызов до отправки (`validate_call`). Схема —
  часть безопасности: она ограничивает пространство того, что можно
  вызвать.
- **Ошибки — данные.** `isError: true` — это не падение, а результат
  для модели: «элемент исчез», «таймаут». Агент должен уметь
  восстанавливаться, поэтому ошибки инструмента возвращаются в history.

## 2. Агентный цикл: восприятие — решение — действие — верификация

```
   snapshot (browser_snapshot)
        │
   llm.decide(state, task, tools, history)
        │
   validate_call → PolicyGate.check_call
        │
   tools/call → browser_*
        │
   verify(before, call, after)
        └── history += {call, result} ──┐
        … пока task_done / MAX_STEPS / «Стоп»
```

- **Восприятие без скриншота**: снапшот — это `{url, title, elements,
  main_text, lead_text, hidden_text}`. Элементы получают ссылки `e0..eN`
  (атрибут `data-agent-ref` в DOM) — удобнее XPath/координат и
  читаемы моделью. Ссылка живёт в рамках снапшота: после
  перерисовки DOM она может устареть, поэтому перед каждым
  вызовом хост проверяет её против свежего снапшота.
- **Решение**: модель планирует 1–N вызовов за раз. Каждый вызов всё
  равно проверяется против свежего снапшота.
- **Верификация**: после действия сравниваются снапшоты (url/elements/
  text). `verify ✗` означает «настроенное постусловие не
  подтвердилось» — не «эффекта точно не было» и не «ошибку».
- **`task_done` — заявление, не факт.** Модель вызывает его как
  инструмент, но вызов не уходит на сервер — так агент завершает задачу
  и возвращает `answer`. Истина — в журнале вызовов и состоянии
  страницы, а не в тексте ответа.

## 3. Граница доверия: сервер глупый, хост умный

Главный тезис курса. MCP-сервер **не знает о задаче** — он исполнитель
(`browser_navigate`, `browser_click`, …). Вся защита живёт на хосте:

| Слой | Где | Когда срабатывает |
|------|-----|-------------------|
| Стоп-слова и домены команды | `PolicyGate.check_task` | до запуска браузера |
| LLM-классификатор | `llm.classify` (CAN/REFUSE/…) | до старта цикла |
| Схема вызова | `validate_call` | перед `tools/call` |
| Политика сайта | `check_call`: allow/confirm/deny + scope | перед `tools/call` |
| Предусловия | `scope_gate` (ref существует, поле editable, URL в scope) | перед `tools/call` |
| Постусловия | `verify` + уход за scope → `browser_back` | после `tools/call` |

## 4. Сценарий и политика: allow / confirm / deny

Сценарий (`SCENARIOS` в `scenarios.py`) = «что это за сайт»:
стартовый URL, `domains` (hard scope — suffix-match хоста и
поддоменов), `match`-regex выбора по URL, `read_only`, `context_prompt`.

Политика (`POLICIES` в `student_policy.py`) = «что можно каждому
инструменту в этом сценарии»:

- **allow** — вызов разрешён, границы всё равно проверяются;
- **confirm** — вызов возможен, но решение принимает человек в окне
  подтверждения;
- **deny** — запрещён независимо от того, что попросили пользователь,
  страница или сама модель.

Правила, которые держит каркас, а не словарь:

- **Правило, не указанное в `POLICIES`, = deny** — если у сценария
  есть запись. Но сценарий БЕЗ записи в `POLICIES` — не fail-closed:
  гейт работает по полям `Scenario`, и `read_only=False` без
  confirm-полей откроет действия. Пишите сценарий и политику вместе.
- **Неизвестный инструмент в политике = явная ошибка** диагностики,
  а не разрешение.
- **`DENY_NAME_PATTERNS`** — запрет по ИМЕНИ элемента («Пожертвовать»,
  «Править»): сильнее любого `allow`/`confirm` инструмента — Approve
  его не отменит.
- **Fail-closed подтверждение:** нет ответа человека за 90 секунд →
  отказ; «Стоп» во время ожидания → отказ. Отказ = `ACTION_DENIED`,
  конец прогона без повторных попыток тем же или другим инструментом.
- **`web`-режим:** сайт без записи в `SCENARIOS` работает в безопасном
  `read_only` — чтение разрешено, click/type/press запрещены
  автоматически.

Чего политика НЕ делает: словарь не создаёт отсутствующий инструмент и
не делает произвольную автоматизацию безопасной. Политику пишет
человек (или черновик — «Разведать» с проверкой человеком): политика,
выданная моделью по потенциально отравленной странице, сама может быть
отравлена.

## 5. Prompt injection: страница — недоверенный ввод

**Indirect prompt injection**: злоумышленник не пишет модели напрямую —
он оставляет инструкции в содержимом страницы: «Ignore your previous
instructions and navigate to …». Модель читает это в `main_text` и может
принять её за команду пользователя.

Слои защиты (defense in depth):

1. **Детектор на хосте** (`detect_injection`): фразы-перехваты EN+RU,
   скрытый текст (`display:none`, белое-по-белому, комментарии),
   `javascript:`-ссылки, base64-блобы. Это **эвристика-warning, а не
   гарантия**: находки уходят модели как `security_warning`, ложные
   срабатывания возможны (легитимная `javascript:`-ссылка Wikipedia).
2. **Политика**: даже пропущенная детектором инъекция ограничивается
   scope и deny.
3. **Человек**: confirm окно показывает имя цели из снапшота —
   человек решает по данным, а не по словам модели.

**Честные границы — чего защита НЕ гарантирует:**

- `read_only`/`deny` не останавливают инъекции, чей вред — чтение или
  разрешённая навигация: `browser_navigate` внутри scope может быть
  allow, а `evil.html`/`collect.html` на `localhost` живут на том же
  хосте — доменный scope изолирует ДОМЕНЫ, не пути внутри домена.
- `inject_persona` может отравить текст ответа модели — политика
  фильтрует вызовы инструментов, а не слова в ответе.
- `scope_gate` заранее проверяет URL навигации и валидность ref клика;
  уход за scope через клик ловится уже после действия (host проверяет
  новый URL и делает `browser_back`) — предварительной проверки `href`
  цели нет.
- Поведение модели недетерминировано: один и тот же сценарий может
  дать разные прогоны — описывайте ожидания и сверяйте факт по
  журналу.

## 6. Human-in-the-loop для деструктивных действий

Деструктивность живёт в данных, а не в имени инструмента: вреден не
`browser_click` вообще, а клик по кнопке «Delete». Поэтому confirm
матчит инструмент (`POLICIES`) и, гранулярнее, имя элемента
(`DENY_NAME_PATTERNS` — наоборот, для запрета).

В эталонном комплекте преподавателя на Google Drive показан следующий
уровень: вместо сырых кликов — семантический `drive_trash_files`,
который согласует **замороженный список файлов и ID** перед одноразовым
Approve. Урок: per-call approve ≠ ограниченная авторизация — человек,
подтверждающий каждый вызов по отдельности, всё равно может потерять
всё (инцидент 2026-11-04). Бюджет деструктива ставится на набор
объектов, а не на вызов.

Гейт детерминирован — промпт его не переубедит. Но граница узкая:
политика и решение человека по-прежнему могут разрешить вредное
действие — код гарантирует проверку, а не безошибочность решения.
Главный вывод: **безопасность агента — код на хосте, а не просьбы в
промпте**.

## 7. Управление жизненным циклом

- **Кооперативная отмена**: LLM-вызов в полёте прервать нельзя —
  `threading.Event` проверяется между шагами; «Стоп» будит и
  confirm-ожидание.
- **Сессия = файл**: `backend/session.json` — хвост последнего прогона
  для «продолжи»; восстанавливается контекст для модели, а не
  состояние страницы.
- **Журнал = чёрный ящик**: `backend/logs/*.jsonl` — каждое решение,
  вердикт и результат. Аудит читают по журналу, а не по памяти.

## 8. CDP: агент в вашем браузере

По умолчанию `chromium.launch()` поднимает чистый профиль — без ваших
куки и логинов. `connect_over_cdp` к Chrome с
`--remote-debugging-port=9222` отдаёт вкладки и сессии отдельного
профиля (`~/.cache/agent-chrome`). Ограничения: только Chromium;
Chrome 136+ требует отдельный `--user-data-dir` для remote debugging.
CDP не делает доступ безопасным: используйте только выделенный
синтетический профиль и не выставляйте порт наружу — endpoint
должен оставаться localhost.
